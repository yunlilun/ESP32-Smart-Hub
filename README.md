# ESP32 Smart Hub (基于ESP32的物联网多模态控制终端)

基于 ESP32 开发的一款多功能集成仪表盘与局域网 Web 控制终端。系统采用非阻塞双核轮询架构，集成了多种环境传感器、生理传感器以及高级继电器定时控制，并配备本地 OLED 交互菜单与完全离线可用的 Web 可视化监控面板。

## 核心功能特性

### 1. 本地 OLED 仪表盘
- **旋转编码器导航**：支持多级菜单平滑滚动、单击确认（进入模式/切换开关）、双击返回。
- **多传感器实时监测**：
  - **倒车雷达**：超声波测距，非阻塞蜂鸣器声光报警（随距离变化响铃频率）。
  - **温湿度读取**：DHT11 环境数据实时显示。
  - **心率监护**：利用 ADC 采样与动态波谷检测算法，实时计算心率 (BPM) 并绘制心电波形。
  - **分贝监测**：基于 ADC 采样计算 Vpp 峰峰值，对数转换显示相对分贝 (dB)。
  - **红外接收**：实时捕捉并显示红外遥控信号状态。
  - **系统状态**：实时监控剩余内存、芯片温度及系统运行时长。

### 2. 高级继电器控制 (Web 与本地双向同步)
- **手动模式**：随时开启或关闭继电器。
- **单次脉冲**：触发一次指定毫秒级（默认 500ms）的脉冲。
- **离线定时 (Local Timer)**：不依赖网络，按设定间隔（如 5 秒）和开启时长（如 2 秒）循环工作。
- **联网定时 (Schedule)**：获取 NTP 网络时间，在指定时间段（如 08:00 开，20:00 关）自动执行。

### 3. 纯离线局域网 Web 控制台
- **零外部依赖**：前端 HTML/CSS/JS 以及波形图表 (原生 Canvas) 全部内置在 ESP32 中，即便无外网，手机连接热点后也能秒开网页。
- **动态可视化**：实时渲染红色心电波形图，以及所有传感器数据的仪表盘。
- **一键配网**：支持在网页端直接输入家庭 WiFi 账号密码，连接外网获取真实时间。

## 硬件接线表

| 模块 | 引脚 | 接 ESP32 | 备注 |
| :--- | :--- | :--- | :--- |
| **OLED 屏幕** | SCL / SDA | GPIO 22 / 21 | I2C 协议，3.3V 供电 |
| **旋转编码器** | CLK / DT / SW | GPIO 32 / 33 / 25 | 需开启内部上拉 |
| **超声波** | Trig / Echo | GPIO 5 / 18 | 建议 5V 供电 |
| **有源蜂鸣器** | I/O | GPIO 4 | 3.3V 供电 |
| **DHT11 温湿度** | DATA | GPIO 15 | 3.3V 供电 |
| **继电器** | IN | GPIO 16 | 5V 供电，注意避开启动敏感引脚 |
| **心跳传感器** | S (模拟) | GPIO 34 | 3.3V 供电 |
| **红外接收** | OUT | GPIO 14 | 3.3V 供电 |
| **声音传感器** | AO (模拟) | GPIO 35 | 3.3V 供电 |

## Web 控制端使用说明

1. 确保设备通电，OLED 屏幕正常工作。
2. 使用手机或电脑搜索 WiFi 热点：`ESP32_Smart_Home`。
3. 输入密码：`12345678` 进行连接（部分手机会提示“无互联网连接”，请选择保持连接）。
4. 打开浏览器，访问局域网 IP：`192.168.4.1` 即可进入暗黑风格的控制面板。
5. 在网页底部的配网输入框中，可填入家中的路由器 WiFi 信息，连接成功后，系统将自动同步网络时间。

## 技术架构与底层优化

- **非阻塞调度**：全系统废弃 `delay()`，采用 `millis()` 时间片轮询，保证 Web 服务、传感器采集和 UI 刷新互不干扰。
- **内存防碎片机制**：针对 ESP32 WebServer 高频请求，使用全局 `char` 缓冲区结合 `snprintf` 替代 `String` 拼接生成 JSON，杜绝长时间运行导致的堆栈溢出和断网死机。
- **硬件防休眠**：强制关闭 WiFi 的 Modem Sleep 模式，确保 Web 客户端随时连接都能获得极速响应。

## 编译环境与依赖

- **开发板**：ESP32 Dev Module (如 ESP32-WROOM-32)
- **开发环境**：Arduino IDE 2.x / Mind+ (基于 Arduino 框架)
- **依赖库**：
  - `U8g2` (OLED 驱动)
  - `DHT sensor library` (温湿度)
  - `Adafruit Unified Sensor` (DHT 依赖)
  - *注：WiFi, WebServer, Wire 等均为 ESP32 官方核心内置库，无需额外安装。*

# ESP32 Smart Hub - 开发历程与版本更新日志 (Engineering Log)

本日志记录了“基于 ESP32 的物联网多模态控制终端”从零搭建、底层排雷、算法优化到最终闭环的完整研发历程。

---

## 阶段一：底层环境与基础硬件打通 (V0.1 - V0.5)

在这个阶段，最大的挑战并非代码，而是底层开发环境与硬件物理特性带来的连环坑。

### 1. 开发环境搭建与库排雷
- **痛点**：Mind+ 在线下载 ESP32 工具链因网络问题频繁中断，且缺失 `DHT`、`U8g2` 等外设驱动库。
- **解决方案**：通过编写 CMD 批处理脚本，直接从 GitHub/Gitee 拉取 `U8g2`、`Adafruit_GFX` 等压缩包，并自动解压至 Mind+ 的本地库目录，彻底绕开网络限制。

### 2. 屏幕点亮的“血泪史”
- **痛点**：OLED 屏幕接电后只亮背光不显示，或者“闪现条纹后熄灭”。
- **排查过程**：
  - 使用 I2C 扫描器确认物理地址为 `0x3C`。
  - 发现面包板接触电阻过大，导致瞬间电流不足以点亮屏幕。
  - 查阅手册发现屏幕驱动芯片为 `NFP1315`，而非标称的普通 SSD1306。
- **解决方案**：缩短杜邦线并重新插紧，将供电改接至 5V 保证电荷泵正常工作；放弃传统的 Adafruit 库，全面采用强大的 `U8g2` 硬件 I2C 库，成功稳定驱动屏幕。

---

## 阶段二：传感器算法优化与 UI 架构搭建 (V0.9.0)

在这个阶段，硬件排雷基本结束，重心转向了多传感器数据的容错处理与多任务架构的设计。

### 1. 心率检测算法重写
- **痛点**：模块输出极度不稳。手不接触时产生假心率；波形频繁拉出贯穿屏幕的长竖线（毛刺）；测出 43 BPM 等极其离谱的数值。
- **解决方案**：
  - 引入**限幅滤波**：若当前 ADC 与上次有效值之差大于 300，直接判定为干扰噪点并丢弃。
  - 引入**动态滑动阈值**：使用过去 30 个采样点的动态极值计算波谷阈值。
  - 引入**在位检测**：通过 ADC 区间（200-2500）过滤，实现“手放上去瞬间出波形，手拿开瞬间提示 Place Finger”。

### 2. 非阻塞多任务改造
- **痛点**：超声波测距或 DHT11 读取时的 `delay()` 会导致屏幕刷新卡顿，且影响网络响应。
- **解决方案**：全局废弃 `delay()`，采用 `millis()` 时间戳轮询调度。结合旋转编码器的状态机（区分单击进入与双击返回），实现了丝滑的多级菜单交互。

### 3. 传感器融合与降噪
- **红外接收**：加入时间戳机制，让接收到的红外信号在屏幕上保持显示 1.5 秒，解决闪烁过快的问题。
- **温湿度读取**：限制 DHT11 读取间隔为 2 秒，且仅在进入温湿度子菜单时才触发，防止拖慢主循环。

---

## 阶段三：Web 物联与系统级瓶颈突破 (V1.0.0 正式版)

进入这一阶段，项目不再是单纯的单机仪器，而是引入 WiFi 与 WebServer，随之而来的是底层内存与网络协议栈的激烈冲突。

### 1. 彻底解决断网与网页卡死
- **痛点**：网页端通过 CDN 引入 ECharts 库，导致手机连接热点（无外网）时网页 JS 崩溃，所有数据全是 `--`；频繁刷新网页导致 `ERR_CONNECTION_RESET`，甚至让 ESP32 的 WiFi 模块死锁。
- **解决方案**：
  - **前端重构**：彻底废弃外部 ECharts，手写原生 HTML5 `<canvas>` 绘制动态心电波形。实现纯局域网、零外部依赖、断网也能秒开网页的极速体验。
  - **后端防崩溃**：废弃高频的 `String` 字符串拼接，改用全局 `char jsonBuffer[2048]` 结合 `snprintf`。彻底根除高并发请求下的堆内存碎片问题。
  - **网络防休眠**：在 `setup()` 中强制加入 `WiFi.setSleep(false);`，禁用底层射频休眠，确保网页随时访问都能即点即开。

### 2. 高级工业级继电器控制
- **痛点**：传统的开/关控制无法满足实际场景。
- **解决方案**：在网页端重构控制面板，新增“单次脉冲（自定义毫秒）”、“离线本地循环定时（Local Timer）”以及“基于 NTP 网络时间的定时计划（Schedule）”。同时确保 OLED 屏幕与网页的状态实现双向强同步。

## 研发复盘 (Review)

从早期的“模块能亮就行”，到后期的“追求极致的界面丝滑与系统低延迟”，这个项目经历了一次典型的创客工程化过程。遇到硬件玄学（屏幕供电、心率干扰）时，学会了用示波器思维（串口打点排查）去溯源；遇到软件崩溃时，学会了从前端 F12 抓包，到后端拆解内存碎片的系统性排查。

**“先跑通，再优化，最后做减法”** 是贯穿整个项目的核心指导思想。
